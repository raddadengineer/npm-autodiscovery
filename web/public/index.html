Supported Container Labels

Attach these labels in your docker-compose.yml or docker run commands to configure automatic proxying:

Label Type Default Description
npm.frontend.domain string Required Domain name(s) for the proxy host. Multiple domains can be comma-separated: app.example.com, web.example.com
npm.frontend.port int Auto-detected Internal container port to route traffic to (e.g., 80, 3000, 8080).
npm.ssl.enabled bool false Enable SSL for this proxy host. (Matches DEFAULT_SSL_ENABLED)
npm.ssl.forced bool false Force HTTP to HTTPS redirect.
npm.forward_scheme string http Forward scheme: http or https.
npm.forward_host string Auto Custom IP/hostname override instead of auto-discovered Docker bridge IP or container name.
npm.certificate_id int / string 0 Existing NPM Certificate ID (e.g. 1) or "new" to request Let's Encrypt.
npm.websocket bool true Allow WebSocket Upgrade headers (essential for socket.io, modern SPAs).
npm.block_exploits bool true Enable NPM's exploit blocking filters.
npm.caching bool false Enable Nginx asset caching.
npm.hsts bool false Enable HTTP Strict Transport Security (HSTS).
npm.enabled bool true Explicitly enable or disable discovery for this container (true or false).
npm.advanced_config string "" Custom Nginx directives inserted directly into the server block.

Quick Example: Docker Compose

Example service showing automatic proxy registration:

version: '3.8'

services:
  my-web-app:
    image: nginx:alpine
    container_name: my-web-app
    restart: unless-stopped
    networks:
      - npm-network
    labels:
      - "npm.frontend.domain=app.mycompany.local"
      - "npm.frontend.port=80"
      - "npm.ssl.enabled=false"
      - "npm.websocket=true"
      - "npm.block_exploits=true"

networks:
  npm-network:
    external: true
💡 Pro Tip: Ensure that your web container and Nginx Proxy Manager share a common Docker network (e.g. npm-network). NPM can then reach the container directly using its Docker DNS container name!
